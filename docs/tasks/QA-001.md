Root approves a separate Mac helper which prepares the next five future weekday
05:50 Brisbane wake events, all owned by
`au.brisbane.transport-resilience.collector`. It must add individual owned events,
never replace the global repeat schedule or clear unrelated events. Default is
prepare/dry-run; explicit installation requires administrator authorization.
Provide the exact administrative commands for user/root execution. Validate the
Mac timezone is Brisbane-compatible before executing events, preserve any existing
schedules, save planned/installed owned events only under ignored `data/runtime`.
No credentials, network requests or cloud resources. A wake schedule does not prove
closed-lid/manual sleep works or guarantee connectivity.

Approved installer refinement: capture the owned macOS GUI `launchctl bootstrap`
result and retry once after 0.5 seconds only for exit code 5. Both attempts use
the same user GUI domain and the same collector plist. Any other or final failure
propagates with captured stdout/stderr. No sudo, global power settings or network
timeout changes are authorized by this refinement.

Coordinator refinement after independent review: minimum per-feed dispatch spacing
is operational interval minus5 seconds (20/20/50). Add the near-phase restart
rapid-success regression and retain the repeated500ms-jitter case. An exact06:00
restart with yesterday's receipt cannot generate a zero-length missing-window
claim; a genuinely late restart still journals missing morning time. Wake events
use `wake` only (no power-on), and existing-event matching must bind kind/date/
owner on the same line, recognizing both two- and four-digit years. A different
owner's event cannot satisfy our owned event even when another line has our owner.
