### Implementation handoff (pending bounded QA)

- Requested/effective dispatch settings are `gpt-6.1-sol`, medium reasoning. Tools cannot introspect backend serving identity; no independent serving identity claim is made.
- Production code implements Decision26 cadence15/15/45, minimum spacing10/10/40, bounded3-connection/90-second shared HTTP client, one retry owner and provider Retry-After handling. Healthy feeds remain separate from a busy feed, schedule, broker and diagnostic persistence.
- `AsyncTelemetry` owns one thread. Status coalesces; log/gap events are retained and retried. `health()` exposes pending/busy/alive/error/disk; `wait_idle()` and injectable writer/logger are bounded QA seams. `close(timeout=30)` raises rather than claiming drain if persistence remains stalled. Events remain in process memory and are not guaranteed after a crash.
- `fetch_feed(..., dispatch=None, telemetry=None)` records phase/submission/task/HTTP timings and returns `runtime_timing` persistence/task completion diagnostics. The real HTTP receipt timestamp is captured before lookup/persistence. `CollectorLoop(..., telemetry=None)` defaults to dedicated telemetry and supports an injected test sink.
- `Archive.recover_pending()` requires `recorder_lock(root)` held and returns recovered IDs/errors. Read-only constructors never recover. Pending envelope path/schema: runtime/pending-captures/<record_id>.json, `{version:1, receipt:<ten-column receipt>}`. Original committed rows are authoritative; corrupt envelopes are retained. Object containment includes resolved archive root and protobuf metadata is checked against hashed payload.
- `outbox_connect()` applies3-second connection/server-statement and1-second lock limits only to outbox. Batches25; failure backoff5 seconds doubling to300; success waits5. Root ratified25-row batches to shorten uninterrupted remote work; they cannot guarantee live60-second shutdown or bound disk stalls. Total backlog has no cap. Existing `remaining` alias preserves within-batch semantics; `pending_references` exposes total unsent references from a worker-side query. Source references remain durable.
- Generated macOS service requests Standard. Awake assertion health checks dead children and retries; Windows assertion remains on its owning thread. No live service restart, global power change, commit/push or production data recovery occurred in this task.
